# EAE-013A — Preview relay session reliability

Scope: staging Supabase `aqizagaskicotorfpwfn`, the isolated Lc0 Preview relay and Arena adapter only. The EAE-013 partial checkpoint is immutable at `e05635155bd4dad88e65ab6ad206989772f19c10`, annotated remotely as `engine-arena-expansion-eae013-preview-partial`. No production deployment, merge, provider registration, COOP/COEP change, engine-strength change, or Arena layout change belongs to this work.

## Original failure and evidence boundary

The final EAE-013 candidate stopped on lifecycle 29 after 28 clean Match lifecycles. Resume returned `SESSION_GONE`; the adapter still reported `READY`, Arena released its runtime records, and the relay table later contained no session. The failed lifecycle had no cooperative `CLEANUP` evidence. No tombstone existed at that time, so its exact original deletion trigger cannot be recovered. Earlier 50/50 success on a different immutable build does not certify that final build.

Before changing live behavior, EAE-013A installed an `AFTER UPDATE OR DELETE` audit trigger on the staging session table. The first instrumentation probe revealed a nullability bug in the new trigger itself: an unlabelled legacy deletion evaluated `NULL = 'EXPLICIT_TERMINATE'` to NULL and blocked the delete. This was repaired by the null-safe follow-up migration; the failed one-cycle probe is not a relay reliability result. A staging-store CAS probe then passed and its `ADMIN_TEST_CLEANUP` tombstone was verified. The original Preview build was stressed against this repaired instrumentation. Its legacy direct deletions are labelled `UNKNOWN`; only the new broker deletion RPC supplies explicit reasons.

The pre-fix immutable deployment `dpl_5oXwg9XfU44REN6LeSiTtS8uLvpr` then reproduced the successful-path failure on cycle **16**, after **15** complete lifecycles (8 White, 7 Black). Resume again surfaced `SESSION_GONE` with adapter phase `READY`, no cooperative cleanup, no Arena runtime residue. Staging audit row `386` records deletion at `2026-09-22 00:29:57.927 UTC` from `STOPPING`, with last ACK `GO`, pending last event `STOP`, no cleanup, both main/engine lease deadlines still about 1.9/2.2 seconds in the future, and the hard TTL about 94 seconds in the future. The `SEARCHING→STOPPING` audit row `385` was at `00:29:55.279`, 2.648 seconds earlier. Source sets `pending.deadline = STOP request time + 2,500 ms`; the STOP ACK had not arrived. No POST request occurred between the last successful heartbeats and deletion. Vercel request logs show the main SSE GET returning 410 immediately afterward, followed by main/engine 410s. Thus the request-time `STOP_TIMEOUT` check in `DurableBroker.mutate` (via SSE `close` after the stream encountered the expired pending command) deleted the row; later Resume requests saw secondary `SESSION_GONE`. The legacy direct-DELETE trigger could only record `UNKNOWN`, but state, deadlines, code path, and request ordering distinguish this timeout from lease, hard TTL, admin cleanup, and explicit owner termination. The original uninstrumented cycle-29 deletion remains unprovable retrospectively; the reproduced cycle-16 failure has the same visible signature and an identified mechanism.

The pre-fix code also contains a separate stale-generation failure path. In `consumeStream`, a heartbeat request from epoch N could remain in flight while the SSE stream reconnected to epoch N+1. The epoch-N request then returned `STREAM_REPLACED`; its unguarded rejection called `fail()`, which immediately sent owner `terminate` against the still-live session. The isolated engine page had a symmetric old-heartbeat callback that could abort the newer stream. This is guarded in EAE-013A but is **not** claimed as the reproduced cycle-16 cause.

## Audit and deletion paths

The staging audit table stores session/competition identifiers, server timestamp, phase before/after, search ID, expiry/lease/last-heartbeat times, pending command/deadline, cursors, command and engine sequence, last ACK/event type, cleanup flag, explicit-terminate flag, deployment URL/ID and request correlation ID where available. It does **not** copy `state` wholesale, owner/auth headers, claim token, engine credential, or token hashes. RLS is enabled, anon/authenticated grants are revoked, and only `service_role` can access the table. The trigger is a backstop: an uninstrumented direct deletion leaves `UNKNOWN`, which fails certification. The cleanup RPC prunes audit rows older than 24 hours when invoked.

The broker hard TTL is 120 seconds per session. The normal EAE-013 Match cycles measured roughly 20–30 seconds, so a hard-expiry explanation for cycle 29 requires a specific outlier or long reuse; it cannot be assumed. Browser `INFO.emittedAt` and other client clocks never authorize deletion. Broker expiry uses serverless server time; staging GC uses its server-supplied `p_now`, not browser time.

## Changes and race invariants

The smallest causal fix gives STOP alone a 10-second acknowledgement deadline instead of the generic 2.5-second command deadline. It remains bounded and does not change the 120-second hard TTL or other command deadlines. A deterministic test proves the reproduced 2.65-second STOP tail can complete through ACK/BESTMOVE/STOPPED, while a genuinely missing STOP ACK still expires at 10 seconds with an explicit `STOP_TIMEOUT` tombstone. The EAE-013A adapter also associates each main heartbeat with its stream controller and lease epoch. A rejection from a replaced stream is ignored. A transient error on the current stream aborts only that controller, then performs authenticated `inspect` and reconnect within the durable lease; an authoritative 410 still fails closed. The engine page applies the same epoch/controller guard. One heartbeat at a time per stream avoids overlapping requests. The broker rejects future reconnect cursors as well as stale cursors without deleting a valid session. The 3-second heartbeat window, 5-second lease grace, origin/auth gates, STOP/BESTMOVE/QUIT/CLEANUP protocol and engine identity/network pins remain unchanged.

Deterministic broker tests run 25 cases each for rapid STOP→Resume, STOP→reconnect→Resume, paused transport interruption within lease, heartbeat at 7.9 s of the 8 s total window, and a replacement broker/main stream (reload analogue). They also reject a late old-generation STOPPED message, stale close, stale heartbeat epoch, stale cursor and future cursor without deleting the live row. These model tests are additional evidence, not substitutes for the real browser soak.
