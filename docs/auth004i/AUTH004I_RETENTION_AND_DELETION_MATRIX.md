# AUTH-004I retention and deletion matrix

No retention period below is represented as enforced unless the implementation column says so. No production data was deleted.

| Data category | Current behavior / purpose | Location and deletion capability | Backup limitation | Proposed rule | Status / approval |
|---|---|---|---|---|---|
| Clerk identity and sessions | Supports login, security and account connection. Sessions have configured expirations; identity persists. | Clerk; identity deletion is provider/admin controlled. | Clerk logs/backups follow provider schedules. | Retain while account is active; evaluate verified deletion request with linked application data. | SAFE DRAFT PROPOSED; implementation and legal review required. |
| CAISSA user and identity binding | Connects Clerk subject to profile, entitlements and saved features. | Supabase; privileged server deletion/update is technically possible. | Database backups can outlive live-row deletion. | Retain while account is active and only as long afterward as needed for integrity/security. | No automated universal erasure; TECHNICAL IMPLEMENTATION REQUIRED. |
| Games, moves, ratings, puzzles, libraries | Provides play history, progress and saved content. | Supabase; category-specific server operations vary. | Provider backups and derived records can remain temporarily. | Keep while feature/account is active; support verified export/deletion subject to game integrity and shared/public records. | Period not chosen; OPERATOR DECISION and legal review required. |
| Access, beta and entitlement records | Authorizes free features and preserves auditability. | Supabase; privileged update/deletion possible. | Backups and security audit evidence may persist. | Retain while access is active plus a proportionate integrity/security period. | Period not chosen; OPERATOR DECISION REQUIRED. |
| Age-gate transient month/year | Candidate evaluates eligibility before Clerk and is designed to discard the values. | Request memory only in candidate; no birth date column. | Ordinary provider request logs must not contain the submitted values. | Never persist month/year after the decision. | Candidate tested, not production; TECHNICAL RELEASE REQUIRED. |
| Invitation, nonce and HMAC quota records | Prevents replay, recipient transfer and abuse. | Supabase candidate tables; expirations and cleanup support exist. | Backups may retain expired rows temporarily. | Enforce code-defined expiry; delete/compact expired operational records on a documented schedule. | Migration not production; TECHNICAL IMPLEMENTATION REQUIRED. |
| Ordinary Scanner source image | Processed to recognize a board; not intentionally stored in app DB/evidence bucket. | Vercel function memory/request path. | Hosting/security logs may contain limited request metadata, not promised source-image erasure. | Do not intentionally persist source image absent separate image-sharing choice. | FACT VERIFIED for app code. |
| Derived Scanner scan snapshot | Operates, diagnoses and evaluates recognition. | Supabase public Scanner tables via privileged server RPC. | Append-only/audit constraints and backups limit immediate deletion. | Define a documented operational/audit retention period and a verified exception workflow. | No period/enforcement; OPERATOR + LEGAL + TECHNICAL required. |
| Optional public feedback | Human-review evidence; starts `raw-unverified`. | Supabase; append-only certification trail. | Audit/backups may remain after live restriction. | Keep while review/use remains active; preserve minimum audit evidence after withdrawal where justified. | No period; OPERATOR + LEGAL required. |
| Optional public feedback image | Improvement evidence when separately selected. | Private Supabase Storage; privileged deletion possible. | No lifecycle rule; backup/provider remnants may remain. | Delete rejected/withdrawn/unbound objects after an approved, technically enforced period. | Current orphan risk; TECHNICAL IMPLEMENTATION REQUIRED. |
| Historical private-beta evidence | Quarantined educational/audit corpus; not eligible by default. | Private tables/bucket; privileged access only. | Backups/provider remnants may remain. | Preserve quarantine; decide item-level consent/provenance before training, export or deletion. | OPERATOR + QUALIFIED LEGAL REVIEW REQUIRED. |
| AI prompts/context and provider key | Generates optional assistance. | Request memory and selected AI provider; result/economic records can exist in Supabase. | Provider retention depends on selected provider/account terms. | Minimize context; never intentionally persist BYO keys; disclose provider processing and apply provider-specific controls before expansion. | FACT VERIFIED / provider review required. |
| Vercel Analytics | Aggregate usage measurement. | Vercel. Query/fragment stripped by loader. | Provider-controlled retention. | Retain only aggregate events under configured provider controls; revisit if analytics changes. | FACT VERIFIED; provider schedule to be confirmed periodically. |
| Browser storage | Preferences, local state, queues and handoffs. | User device; user can clear it. | Browser sync/backups are user/provider controlled. | Expire or replace temporary entries where code supports it; document user clearing. | Partially implemented. |
| Security/request logs | Abuse prevention, availability and incident response. | Vercel, Clerk, Cloudflare, Supabase and selected services. | Provider-controlled retention and backups. | Use provider defaults only while proportionate; document any custom extension. | Exact consolidated periods not verified. |

## Required implementation backlog

1. Atomic or recoverable Scanner image-to-feedback binding and orphan cleanup.
2. Category-aware verified export/deletion executor; Clerk deletion alone must not be treated as full erasure.
3. Retention jobs only after the operator and counsel approve specific periods.
4. Versioned policy-notice record and re-consent mechanism if the final policy requires it.
5. Monitoring that confirms transient age inputs are absent from application logs, analytics and storage.
