# ChessBase Live Tournaments integration audit (LTR-0.1)

**Verdict: CONDITIONAL GO.** CAISSA can display a provider-selected current live tournament automatically with the documented wildcard `.cblive` mode. That is suitable only for a generic “current live tournament” promise. ChessBase does not document how the wildcard chooses among simultaneous events, so a named or editorially featured tournament requires an operator to configure the event identifier. The operator does not need to maintain a date or round when the official event iframe or `data-round="max"` is used.

Audit date: 2026-08-15 UTC. Observation window: 2026-08-15 01:57–02:05 UTC. This is an engineering, product, privacy, and supply-chain assessment, not legal advice.

## 2. Required repository ownership trace

The released Game Replayer has three separate owners:

1. `game-replayer.html` owns indexable page copy, shared navigation, status/error UI, retry/download fallback, attribution, and the titled iframe.
2. `js/game-replayer-parent.js` owns a 15-second timeout, isolated iframe reload, and the exact-origin/source `CaissaGameReplayerStatus@1.0.0` protocol.
3. `integrations/chessbase-pgn-replayer.html` owns the SRI-pinned ChessBase CSS, jQuery 3.0.0, `cbreplay.js`, wrapper-local CSP, and the PGN-specific `.cbreplay` host. `js/chessbase-pgn-replayer-wrapper.js` observes provider render/failure and emits the bounded status schema.

Production header ownership for that wrapper is in `vercel.json`. External-script discovery and the exact SRI registry are owned by `scripts/supply-chain-script-tags.mjs` and `scripts/audit-supply-chain.mjs`. Navigation order is owned only by `CaissaGlobalNavigationOrderPolicy@1.6.0`; deterministic fallback and route inventory outputs are generated by their canonical scripts. Live Blitz is a distinct cross-origin iframe gateway with CAISSA-owned attribution and fallback copy; it does not load ChessBase scripts in the parent.

### Reuse classification

| Component | Classification | LTR consequence |
| --- | --- | --- |
| Parent SEO, H1, attribution, visible fallback, titled iframe | directly reusable pattern | Copy the ownership pattern, not GPR-specific text or route values. |
| Parent timeout, exact source/origin messages, retry-by-iframe-reload | reusable with a new schema/mode | Use only if CAISSA owns a first-party live wrapper. An official cross-origin iframe cannot emit the GPR protocol without provider support. |
| First-party ChessBase wrapper boundary | reusable with mode/configuration | `.cblive` can replace `.cbreplay`, but live network policy and readiness signals require fresh certification. |
| ChessBase CSS, jQuery, `cbreplay.js`, SRI pins and scanner registrations | directly reusable only while live hashes still match | The official live documentation names the same three assets. Revalidate immediately before any implementation release. |
| `sandbox="allow-scripts allow-same-origin"` limitation | security evidence reusable | It is not a parent-DOM isolation boundary. Do not describe it as one. |
| Capablanca PGN, `data-url`, provenance sidecar, validation copy, download | PGN-specific; not reusable | A live broadcast is provider data and must not be copied into the GPR collection flow. |
| `.cbreplay` MutationObserver readiness heuristic | PGN-specific in current form | Live mode can render an empty shell, reconnect, or change rounds; define a live-specific readiness/idle/error contract. |
| Wrapper CSP `connect-src` | security-sensitive; not reusable unchanged | Live mode requires ChessBase live HTTP/WebSocket origins not allowed by GPR. |
| Live Blitz attribution language | directly reusable pattern | Preserve provider ownership and state that CAISSA neither operates nor guarantees the tournament feed. |

### Official documented plugin markup

```html
<div class="cblive" data-event="*" data-date="*"></div>
```

ChessBase says an event substring such as `Wijk` may replace `*`, and a fixed round may be selected with `data-round="4"`. The same page requires the CBReplay stylesheet, jQuery, and `cbreplay.js` already used by GPR.

The current “For Webmasters” output for the active event was:

```html
<iframe src='https://live.chessbase.com/frame/Esports-World-Cup-Chess-Playoff-2026'
        width="900" height="600"></iframe>

<iframe src="https://live.chessbase.com/pgn/esports-world-cup-chess-playoff-2026/0"
        width="900" height="600"></iframe>

<div class="cblive" data-event="Esports-World-Cup-Chess-Playoff-2026"></div>
```

ChessBase documents `/0` as all completed rounds and says `data-round="max"` limits plugin results to the current round. The generated live frame itself used the exact event identifier and `data-round="max"`.

## 4. Decisive automatic-selection test

The official documentation page was loaded without an account and without changing its literal wildcard markup. On 2026-08-15 UTC it automatically rendered:

- `Live: FIDE ISCF WSTC-ch Americas 2026`;
- location/date `San Jose 15.08.2026`;
- games from round `6`;
- player names, live/completed results, clocks/moves, Games, Notation, Chat, and navigation controls.

This proves that `data-event="*" data-date="*"` can automatically produce a useful current broadcast. It does **not** establish an editorial selection contract. The selected FIDE ISCF event was not the directory's headline Esports World Cup event, and the documentation gives no priority, quality, rating, locale, popularity, continuity, or fallback algorithm for `*`.

**Product answer:**

- Generic promise — “watch a current live tournament”: technically automatic; no operator event/date/round update is required while ChessBase returns a wildcard match.
- Curated promise — “watch this featured tournament”: operator configuration of the event identifier is required for each featured event.
- Date: not required for the official event-specific frame and unnecessary when the event ID is exact.
- Round: not required for live current-round behavior; the generated frame and plugin support `data-round="max"`. A numeric round is needed only when CAISSA intentionally pins a historical round.

There is no documented API, webhook, feed-ranking contract, stable “featured event” identifier, or callback that lets CAISSA choose the directory's best event automatically. CAISSA must not scrape the directory to invent one.

## 5. Runtime and network findings

Static inspection of the currently SRI-pinned `cbreplay.js` confirms that `.cblive` is a first-class mode. It copies `data-event`, `data-round`, `data-date`, player/team filters, and other dataset fields into a live request. `max`/`highest` becomes a `highestRoundOnly` flag. Wildcards are sent to the provider; selection is not performed by CAISSA.

The documentation page's observable asset inventory contained 102 resources: 6 scripts, 6 stylesheets, 44 images, 5 fonts, and 41 other resources. Its script set included page-owned bundles, the current `cbreplay.js`, ChessBase engine scripts, and advertising code. Those full-page dependencies are not a valid CAISSA allowlist. A future implementation must trace only the chosen isolated mechanism from a clean profile.

The official `/frame/{event}` response was deliberately frameable: no blocking `X-Frame-Options` or `frame-ancestors` header was observed. It is nevertheless a full provider document with its own cookie/privacy and runtime behavior, not an inert board iframe.

## 6. Security, privacy, accessibility, and failure analysis

### Official cross-origin frame

Advantages:

- real browser-origin isolation from CAISSA parent DOM, storage, cookies, and application globals;
- no ChessBase jQuery or script in the CAISSA parent or first-party wrapper;
- no CAISSA SRI registry entry is needed for scripts inside the provider-owned document;
- provider owns live reconnection and current-round behavior.

Costs:

- CAISSA cannot SRI-pin, CSP-govern, inspect, or version the frame's internal scripts;
- the provider page can change without a CAISSA commit;
- provider cookies, technically necessary state, optional analytics/marketing, account links, chat, engine, share, advertising, or other features may appear;
- CAISSA cannot reliably detect semantic readiness or distinguish “no games yet” from failure without a documented message API;
- provider accessibility remains only partially controlled.

### First-party `.cblive` wrapper

Advantages:

- reuses the GPR dependency pins, supply-chain scanner, CAISSA status/fallback protocol, and narrow wrapper ownership;
- can use the documented wildcard automatic mode without maintaining an event ID;
- can exclude full-page advertising and analytics if isolated runtime traces prove they are unnecessary.

Costs:

- requires new `connect-src`/WebSocket allowances and fresh failure/reconnect tests;
- retains GPR's accepted same-origin sandbox limitation: `allow-scripts allow-same-origin` is not DOM isolation;
- live provider code obtains first-party wrapper origin privileges and continuously processes remote data;
- wildcard selection is provider-defined and unstable;
- readiness, no-event, stale-event, disconnect, reconnect, round rollover, large-event, and timeout behavior are uncertified.

ChessBase's privacy statement identifies technically necessary ChessBase cookies, last-game state, account tokens when used, analytics cookies, and marketing technologies. No account was created or used during this audit. A CAISSA page must disclose provider operation and must not imply that CAISSA controls the feed, players, clocks, results, event selection, or ChessBase privacy behavior.

Provider accessibility positives include named Games/Notation controls, native buttons, tables, and usable visible game metadata. Limitations inherited from CBReplay include dense toolbars, title-dependent icons, small targets, incomplete board semantics, chat/account affordances, and no published accessibility conformance statement. The CAISSA parent must supply one H1, explanatory text, a titled iframe, status/fallback semantics, an official open-in-new-tab link, visible attribution, keyboard-visible focus, and a non-script description of the current configuration.

## 7. Architecture options

| Option | Automation | Security/maintenance | Verdict |
| --- | --- | --- | --- |
| Direct `.cblive` in the public CAISSA page | wildcard or fixed event | jQuery collision, shared CSP expansion, remote live code receives full page privileges | reject |
| Reuse GPR same-origin wrapper with `.cblive` mode | wildcard automatic or fixed event; `max` round | maximum code reuse, but requires live WebSocket CSP and repeats the non-isolating sandbox limitation | conditional for an explicitly generic automatic feed |
| Official cross-origin `/frame/{event-id}` iframe | exact event; round follows automatically | smallest curated implementation and strongest parent isolation; provider internals remain mutable/opaque | **recommend for a named featured broadcast** |
| Official `/pgn/{event-id}/0` iframe | completed games, not the live board | useful secondary/archive fallback, not a live-first product | optional fallback only |
| Scrape/index/select events in CAISSA | could automate editorial selection | violates task scope, provider authority, maintenance, and reuse-first constraints | reject |
| Native viewer/backend/database | CAISSA-controlled | unnecessary large system and prohibited scope | reject |

## 8. Recommended sustainable architecture

Use a **configuration-driven official cross-origin event iframe** for the first public release:

```text
CAISSA parent page
  owns navigation, SEO, H1, introduction, attribution, loading/fallback copy,
  official open-in-new-tab link, and a single reviewed event configuration
    -> cross-origin https://live.chessbase.com/frame/{event-id}
       owns live data, rendering, reconnection, and current-round selection
```

Store only a small reviewed configuration record such as:

```json
{
  "schema": "CaissaLiveTournamentConfiguration@1.0.0",
  "eventId": "Esports-World-Cup-Chess-Playoff-2026",
  "displayName": "Esports World Cup Chess-Playoff 2026",
  "officialUrl": "https://live.chessbase.com/en/Watch?id=Esports-World-Cup-Chess-Playoff-2026",
  "reviewedAt": "2026-08-15T00:00:00Z",
  "status": "active"
}
```

This is not a tournament database or ingestion service. One operator change per featured event is the honest cost of editorial control. The event iframe follows the current round, so do not add date/round operations unless a product requirement explicitly pins them.

If product leadership instead chooses an uncurated generic feed, reuse the existing GPR wrapper as a **separate live mode** with literal `data-event="*" data-date="*"`. Do not overload the Capablanca wrapper URL or controller. That path requires a separate LTR security implementation task to measure exact live origins, revalidate SRI, define live-specific status/reconnect behavior, and disclose that event choice belongs to ChessBase.

Do not create a generic wrapper framework. Share small constants or parent-controller helpers only after two concrete modes prove identical behavior; premature abstraction would obscure different trust and failure models.

## 9. Proposed product contract

- Suggested route for a later task: `/watch/live-tournaments`.
- Suggested label: `Live Tournaments` under Analyze & Watch, placement to be reconciled separately with the canonical navigation policy.
- H1 should identify live tournament viewing without claiming CAISSA operates the broadcast.
- Visible disclosure: ChessBase provides and operates the tournament feed; CAISSA selects and embeds a public event link and does not control availability, clocks, pairings, moves, results, or event data.
- Empty/failure state: retain explanation and an official ChessBase link; never invent “live now” when readiness is unknown.
- Do not expose chat, login, engine, account, or Premium as CAISSA features.
- Do not promise a named event in metadata unless the reviewed configuration is current and the release process owns updating it.

## 10. Implementation release gates

Before LTR implementation:

1. Product chooses **curated/manual event ID** or **generic/provider-selected wildcard** explicitly.
2. Confirm current ChessBase webmaster markup and frameability.
3. Revalidate all reused SRI hashes if the wrapper option is chosen.
4. Capture a clean network trace for active, idle, completed, disconnected, reconnecting, and round-rollover states.
5. Establish exact CSP ownership without ChessBase wildcards or global `unsafe-eval`.
6. Test 1440, 1024, 768, 390, and 320 CSS px plus keyboard and 200% zoom.
7. Prove a useful fallback when the event is missing, finished, delayed, blocked, or renamed.
8. Verify parent horizontal containment, mobile drawer behavior, and one primary navigation landmark.
9. Document provider-owned accessibility limitations and privacy/cookie behavior.
10. Add route/navigation/sitemap/inventory changes only in the implementation task and regenerate only canonical deterministic outputs.

## 11. Final decision

**CONDITIONAL GO — CURATED OFFICIAL EVENT IFRAME RECOMMENDED.**

The wildcard mode proves CAISSA can automatically show a current live tournament, but it cannot guarantee which tournament ChessBase selects. The smallest sustainable architecture for a dependable named CAISSA surface is therefore a reviewed event ID in the official cross-origin ChessBase frame, updated once per featured broadcast. Current round selection remains automatic. Reuse GPR's outer-page, attribution, fallback, and certification patterns; do not reuse its PGN content contract or assume its live-network policy.
